# 关键技术点

## 1. JSON Schema 驱动的动态表单

LabelHub 不在标注页面硬编码业务字段。任务负责人通过 `Task.formSchema` 配置标注字段，`FormRenderer` 根据 schema 渲染 radio、checkbox、select、rating、textarea、text、boolean 等字段。

`FormSchemaEditor` 支持字段编辑、复制、排序、required、helpText、defaultValue、validation、实时预览和 JSON 查看，便于比赛展示“可配置标注平台”的能力。

下图展示 Task Builder 中任务负责人配置动态表单和预览 schema 的过程。

![Task Builder 动态表单配置](images/03-task-builder.png)

## 2. 通用样本数据展示

`SampleDataViewer` 直接基于 `sample.rawData` 的任意 JSON 展示数据。它不会读取 `user_query`、`model_answer`、`reference_answer` 等特定字段，因此客服 QA、RAG 评测、Agent trace 等样本都可以复用同一展示组件。

下图展示通用 rawData 区域和 schema 驱动表单在标注员工作台中的组合。

![Annotate 标注工作台](images/04-annotate.png)

## 3. QualityGuard Agent

QualityGuard Agent 的输入包括：

- task instruction
- reviewRubric
- formSchema
- sample rawData
- annotationData

Agent 通过 prompt 模板生成 rubric-based 审核提示，要求输出严格结构化 JSON。当前本地 Demo 默认使用 `MockProvider`，根据必填缺失、类型不匹配、低评分、短文本说明和通用风险关键词等规则生成可解释预审结果。`OpenAIProvider` 为占位实现，真实 API Key 必须来自 `OPENAI_API_KEY`。

下图展示 QualityGuard Agent 的风险等级、建议、问题列表和 rubric evidence 如何辅助人工审核。

![Review 人工审核工作台](images/05-review.png)

## 4. 工作流状态机

样本状态流转集中放在 `lib/workflow/statusMachine.ts`。标注提交、AI 预审、人工审核和导出都通过状态机更新 Sample 状态，避免 API 和页面到处硬编码状态跳转。

下图展示工作流状态、审核进度和质量风险在 Dashboard 看板中的汇总效果。

![Dashboard 质量看板](images/01-dashboard.png)

任务管理页面展示了不同类型数据生产任务的队列状态，包括任务名称、样本规模、提交进度和当前审核状态，体现平台对多任务数据生产流程的统一管理能力。

![任务管理页面](images/02-task-management.png)

## 5. formSchema 版本管理

每次更新任务表单时会创建 `FormSchemaVersion`，`Task.currentFormSchemaVersionId` 指向最新版本。标注提交时记录 `Annotation.formSchemaVersionId`，避免历史标注被后续表单修改影响。

## 6. 数据导出

导出默认只包含 APPROVED 样本，支持：

- JSON
- CSV
- JSONL
- OpenAI fine-tuning style JSONL

导出时可以选择是否包含 AI 预审、人工审核和任务元数据，并生成 `ExportJob` 记录。

下图展示 Export 页面中的多格式导出、导出选项和预览能力。

![Export 数据导出中心](images/06-export.png)

## 7. 审计日志

`AuditLog` 记录任务创建、表单更新、样本分配、标注提交、AI 预审、人工审核和导出等关键动作。日志只记录轻量 metadata，不复制完整 rawData。

## 8. 轻量 RBAC

当前实现了 mock 当前用户和角色权限控制，角色包括 ADMIN、TASK_OWNER、ANNOTATOR、REVIEWER。API route 会进行权限检查，页面会隐藏不可用操作。该能力用于 Demo 和工程结构展示，暂未接入真实认证系统。
