# 演示环境与 Vercel 部署说明

当前提交版本支持本地完整运行与演示视频复现。由于线上 serverless 环境对 SQLite 持久化支持有限，线上部署建议使用 Vercel + PostgreSQL。本文档已提供部署步骤，评委可通过本地启动和演示视频查看完整链路。

本文档基于当前真实代码编写，用于比赛演示环境准备和 Vercel 部署前检查。当前项目是 Next.js + Prisma + SQLite local Demo；如果要做稳定线上演示，需要把数据库切换到外部持久化数据库。

## 演示方式

- 当前提交版本以本地完整运行和 GitHub Release 演示视频为准；线上部署建议使用 Vercel + PostgreSQL，部署步骤见下文。
- GitHub 仓库地址：https://github.com/yuansiyuanxjtu/labelhub-ai-platform
- Demo 视频地址：见 `submission/video/demo-video-link.md`

## 部署适配性检查

| 检查项 | 当前状态 | 说明 |
| --- | --- | --- |
| Next.js 是否适合 Vercel | 基本适合 | 项目使用 Next.js App Router，`package.json` 中 `build` 为 `next build`。 |
| Prisma 是否可用于 Vercel | 可以，但需注意生成 client | 当前有 `prisma:generate` 脚本，但 `build` 没有自动串联 `prisma generate`。 |
| 当前数据库是否适合 Vercel | 不适合持久化 | `prisma/schema.prisma` 当前 datasource 为 SQLite，`DATABASE_URL=file:./dev.db`。Vercel serverless 文件系统不适合作为持久数据库。 |
| 是否需要生产数据库 | 需要 | 推荐 Neon、Supabase PostgreSQL 或其他外部 PostgreSQL。 |
| `.env.example` 是否完整 | 已补充 | 当前包含 `DATABASE_URL`、mock AI provider、OpenAI API Key 占位和本地 App URL。 |
| 是否需要 seed demo data | 需要 | 线上演示需要先执行 seed，或通过 `/demo` 页面 Reset demo data。 |
| 是否需要真实 AI API | 不需要 | 比赛 Demo 使用 `AI_PROVIDER=mock`，不会调用真实模型 API。 |

## Vercel 部署步骤

### 1. 连接仓库

1. 登录 Vercel。
2. Import Git Repository。
3. 选择 LabelHub 仓库。
4. Framework Preset 选择 `Next.js`。

### 2. 安装与构建命令

当前 `package.json`：

```json
{
  "scripts": {
    "build": "next build",
    "prisma:generate": "PRISMA_CLIENT_ENGINE_TYPE=binary PRISMA_CLI_QUERY_ENGINE_TYPE=binary prisma generate",
    "prisma:migrate": "PRISMA_CLIENT_ENGINE_TYPE=binary PRISMA_CLI_QUERY_ENGINE_TYPE=binary prisma migrate dev",
    "prisma:migrate:deploy": "PRISMA_CLIENT_ENGINE_TYPE=binary PRISMA_CLI_QUERY_ENGINE_TYPE=binary prisma migrate deploy",
    "prisma:seed": "PRISMA_CLIENT_ENGINE_TYPE=binary PRISMA_CLI_QUERY_ENGINE_TYPE=binary prisma db seed",
    "db:seed": "npm run prisma:seed"
  }
}
```

Vercel 推荐 Build Command：

```bash
npm run prisma:generate && npm run build
```

如果使用 pnpm：

```bash
pnpm run prisma:generate && pnpm run build
```

说明：当前仓库没有 `postinstall` 自动执行 Prisma Client 生成，因此 Vercel 构建阶段需要显式执行 `prisma generate`。

### 3. 部署前验证

本地先运行：

```bash
npm install
npm run prisma:generate
npm run prisma:migrate
npm run db:seed
npm run lint
npm run typecheck
npm run test
npm run build
```

## 数据库配置步骤

### 当前 SQLite 状态

当前 Prisma datasource：

```prisma
datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}
```

本地 `.env.example` 当前内容：

```bash
DATABASE_URL="file:./dev.db"
AI_PROVIDER="mock"
QUALITY_GUARD_PROVIDER="mock"
OPENAI_API_KEY=""
NEXT_PUBLIC_APP_URL="http://localhost:3000"
```

这适合本地 Demo，但不适合 Vercel 上的持久化演示。Vercel serverless 环境中的本地文件不能作为可靠持久数据库使用，部署重启、冷启动或实例变化后都可能导致数据不可用或不可预期。

### 推荐生产演示方案：PostgreSQL

推荐使用 Neon 或 Supabase PostgreSQL。

步骤：

1. 在 Neon 或 Supabase 创建 PostgreSQL 数据库。
2. 获取数据库连接字符串。
3. 在 Vercel Project Settings -> Environment Variables 中配置 `DATABASE_URL`。
4. 将 Prisma datasource provider 从 `sqlite` 切换为 `postgresql`。
5. 为 PostgreSQL 重新生成 migration，并执行生产迁移。
6. 执行 seed，生成 Demo 数据。

PostgreSQL datasource 示例：

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

PostgreSQL `DATABASE_URL` 示例：

```bash
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require"
```

注意：当前代码仓库还没有完成 PostgreSQL provider 切换，本说明将其列为线上持久 Demo 的部署前必要步骤。不要直接把 `file:./dev.db` 当作 Vercel 生产数据库。

### 数据迁移建议

本地开发脚本 `npm run prisma:migrate` 使用的是 `prisma migrate dev`，适合本地开发。

线上部署建议使用：

```bash
npm run prisma:migrate:deploy
```

当前 `prisma:migrate:deploy` 脚本已提供，但当前 Prisma datasource 仍是 SQLite。若切换 PostgreSQL，需要先重新确认 migration 与 provider 配置。

## 环境变量清单

### 必填

```bash
DATABASE_URL="file:./dev.db"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
```

本地 Demo 使用 SQLite 文件。线上 Vercel 持久演示应将 `DATABASE_URL` 替换为 PostgreSQL 连接字符串，并将 `NEXT_PUBLIC_APP_URL` 改为线上地址。

### 推荐

```bash
AI_PROVIDER="mock"
```

用于明确使用本地 mock QualityGuard provider，避免误切到真实 provider。

### 可选

```bash
QUALITY_GUARD_PROVIDER="mock"
OPENAI_API_KEY=""
```

说明：

- `QUALITY_GUARD_PROVIDER` 与 `AI_PROVIDER` 都可影响 provider 选择。
- `OPENAI_API_KEY` 只在后续真实 OpenAI provider 接入时需要。
- 当前 `OpenAIProvider` 是占位实现，比赛 Demo 应保持 `AI_PROVIDER=mock`。

## Demo Mode 使用说明

LabelHub 提供 `/demo` 页面用于比赛演示。评委可以通过 Demo Mode 重置数据、切换 mock 角色，并进入标注员或审核员视角体验主链路。

### Demo 数据

seed 和 Demo Mode 会生成 3 类任务：

- 客服问答质量评估
- RAG 回答事实性评估
- Agent 工具调用轨迹评估

每类任务包含 instruction、reviewRubric、formSchema、样本、部分 annotation、部分 AI review 和部分 human review。

### 推荐演示顺序

1. 进入 `/dashboard` 查看质量看板。
2. 进入 `/demo`，点击 Reset demo data。
3. 进入 `/tasks/new`，选择任务模板并展示动态表单配置。
4. 进入 `/annotate`，选择样本并提交标注。
5. 触发 QualityGuard AI 预审。本地和比赛 Demo 使用 mock provider。
6. 进入 `/review`，查看 AI 风险、rubric evidence 和人工审核表单。
7. 进入 `/exports`，选择任务和导出格式，预览前 3 条数据并下载。

## seed Demo Data

本地 seed：

```bash
npm run prisma:seed
```

等价命令：

```bash
npm run db:seed
```

线上 seed 可选方案：

1. 在本地连接线上 `DATABASE_URL` 后执行 `npm run prisma:seed`。
2. 部署后以 ADMIN mock 角色访问 `/demo`，点击 Reset demo data。

注意：线上数据库 seed 会重置演示数据，正式评审前应提前确认当前展示数据符合预期。

## 已知限制

- 当前 Prisma provider 是 SQLite，直接部署到 Vercel 不适合作为持久化线上 Demo。
- 若使用 Neon/Supabase PostgreSQL，需要切换 Prisma datasource provider 并重新处理 migration。
- 当前 `build` 命令没有自动运行 `prisma generate`，Vercel Build Command 需要显式串联。
- 当前 `prisma:migrate` 使用 `migrate dev`，线上应改用 `npm run prisma:migrate:deploy`。
- Demo Mode 使用 mock 当前用户和 mock RBAC，不是真实登录系统。
- QualityGuard 的 OpenAI provider 仍是占位实现；线上 Demo 建议使用 `AI_PROVIDER=mock`。
- 导出文件通过浏览器下载，没有接入对象存储或异步导出任务。
